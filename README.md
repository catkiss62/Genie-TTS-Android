# Genie-TTS Android

这是一个面向 Android ARM64 手机的 Genie-TTS v2.0.2 真机验证项目。

开发结论、测试数据、私有资源说明和后续接入清单集中记录在 [PROJECT_LEDGER.md](PROJECT_LEDGER.md)。准备移植到 AI 伴侣时直接阅读 [AI_COMPANION_INTEGRATION_GUIDE.md](AI_COMPANION_INTEGRATION_GUIDE.md)。

## v0.6.3：Android 接入收口基线

v0.6.2 已完成目标手机三语长文本听感验证。本版不改模型、前端、采样、线程或播放策略，只整理正式命名与接入边界：

- 测试音色改名为“日常认真（主音色）”“温柔轻声”“活泼可爱”“日常可爱”“备选音色（仅测试项目）”；底层稳定 ID 与参考资源不变；
- 正式 AI 伴侣仅移植前四种音色，备选音色继续留在本测试项目；
- 记录“自动匹配情绪 / 固定单一音色”两类设置语义；固定模式完全覆盖情绪映射；
- 新增独立接入指南，明确三语前端生命周期、19 种情绪映射、现有真流式队列复用方式、串行推理约束和 v0.6.1 禁止重踩项。

v0.6.3 APK 仍保留全部测试、回放和诊断能力，用于以后从备选音色取回资源或做回归对照。

## v0.6.2：三语长文本回归隔离

本版只用于定位 v0.6.1 的中文长文本性能回退，不改模型、RoBERTa、音素、采样参数或 CPU 线程数：

- 恢复 v0.5.0 的固定 1 秒首段预填充，移除 v0.6.1 的自适应预填充；
- 取消 Activity 启动后的后台 TTS 会话预热；英文 CMUdict 与日语 OpenJTalk 改为首次使用对应语言时才初始化；
- 保留 v0.6.1 已通过的整页滚动与系统导航栏避让；
- 新增中文、英文、日文三项约 500 字符长文本试听，三种语言继续复用同一套声学模型，但前端按语言隔离；
- 长文本报告只保留最后一次结果。某种语言听感或停顿异常时，应立即复制该语言报告，再运行下一种语言。

安装后应先冷启动并只运行中文长文本，确认它是否恢复 v0.5.0 的连续性；中文通过后再分别运行英文和日文。约 1000 字的模拟 DeepSeek 真流式测试暂不叠加，避免同时改变多个变量。

## v0.6.1：未通过的体验优化实验

v0.6.0 已经通过目标手机听感测试，中英混合、纯英文和纯日语均可正常播放。本版不修改模型、音素、BERT、采样参数或 CPU 线程数，只处理接入前的低风险工程问题：

- 将整个测试页面改为可滚动布局，并按状态栏、虚拟导航栏动态增加安全边距；底部回放与报告按钮不会再被系统导航键遮挡；
- 页面启动后在同一串行工作队列中后台释放资源并预热四个 TTS ONNX 会话；用户点击生成时继续复用，自动诊断仍会主动卸载以保留冷/热对照；
- 约 500 字流式测试根据首段实际 RTF 和音频长度，在 0.75–2.5 秒之间选择 AudioTrack 首段预填充，降低第一段后停顿概率；
- 报告明确记录预填充时长。真机结果显示该版中文 505 字长文本聚合 RTF 达 2.475，15/15 个后续段迟到并发生 15 次 underrun，因此不得作为接入基线。

## v0.6.0：手机端动态中英日三语前端

在 v0.5.0 已证实恬豆权重具备三语声学能力后，本版把固定音素验证扩展为运行时前端：

- 中文模式允许句中混入英文。中文片段只运行一次 INT8 Chinese RoBERTa，英文片段使用 CMUdict/ARPAbet 与零 BERT，最后合成一条序列并只运行一次 TTS；
- 内置 `DeepSeek`、`token`、`AI`、`API`、`GPT`、`CPU`、`GPU`、`ONNX` 热词，未命中的英文先查 CMUdict，仍未命中时逐字母读出，不会静默跳过；
- 纯英文模式独立使用 CMUdict/ARPAbet；纯日语模式独立使用 Android 原生 OpenJTalk 1.11；
- 英文与日语继续遵循 Genie 官方做法使用零 BERT，不增加第二套语言模型；
- 新增 4 条中英混合、4 条英文、4 条日语预设。英日预设会将手机端动态音素与桌面官方前端的黄金序列比较，差异直接写入报告。

OpenJTalk 词典原始大小约 103 MB，APK 压缩后的增量明显更小；首次运行日语时会释放到应用私有目录，后续直接复用。公开仓库不提交这些二进制资源，维护者可运行 `Prepare OpenJTalk Android assets` 工作流取得固定版本资源，再放入对应的 `assets/openjtalk` 与 `jniLibs/arm64-v8a` 目录。

## v0.5.0：恬豆 V2 三语声学能力验证

新增“生成并播放英语测试”和“生成并播放日语测试”两个独立按钮。英语固定句使用 Genie v2 的 ARPAbet 音素，日语固定句使用 Genie 的 OpenJTalk 音素（含重音与促音标记）；两者均按 Genie 官方推理逻辑使用全零 BERT。按钮跟随当前候选参考音色，完整运行 GPT 与 SoVITS，并生成可复制的推理报告。

这一版刻意使用预先核对的固定音素，不捆绑英文生词 G2P 或完整日语形态分析器：它要回答的是“这套恬豆权重本身是否学过英语和日语”，避免把前端移植问题混入听感结论。英语句子包含 `DeepSeek` 和 `token`，其中 `token` 使用标准非重读元音；日语句子用于检查假名、重音、停顿和音色保持。

固定英日测试几乎不增加 APK 体积。目前任意自由输入仍以中文前端为主：拉丁单词按既有规则逐字母转写，混入的日语假名会被明确记录并忽略；纯日语请使用专用日语测试按钮。如果英日固定测试听感成立，下一步再移植任意英文 G2P，并单独评估完整日语前端的体积和 Android 兼容性。

## v0.4.1：轻量英文逐字母转写

不增加英文或日语大模型，保留现有 Chinese RoBERTa 和 TTS 推理链。自由输入中的拉丁字母会在进入中文前端前转换为中文字母读音，保证不会被静默跳过；大小写均支持，单词 `token` 固定转换为“拖肯”。界面新增一键填入 `API / GPT / token` 的测试台词。

这不是完整英文 G2P：除 `token` 外，英文单词按字母逐个读出。日语 G2P 未加入，检测到平假名或片假名时会明确提示，不会静默删除。约 500 字分段流式、模型、采样参数和五个候选音色均保持 v0.4.0 不变。

## v0.4.0：约 500 字真分段流式测试

在 v0.3.3 已确认的完整 RoBERTa、CPU 8 线程和五个候选音色基础上，新增约 500 字的长文本流式测试。长文本按自然标点切成不超过 54 字符的片段；首段生成后立即通过 `AudioTrack.MODE_STREAM` 开播，推理线程在播放期间继续生成并排队后续片段，不修改 Genie 的采样参数。

长文本报告记录首段等待、逐段前处理/核心推理/RTF、入队前缓冲余量、迟到片段、AudioTrack underrun、峰值 PSS 和总墙钟时间。测试音色跟随界面当前选择；运行前需要导入与 v0.3.2 相同的外置 INT8 Chinese RoBERTa。

## v0.3.3：音色收敛与常驻性能测试

测试音色已收敛并重新命名：日常认真（原候选 1）作为主音色，温柔轻声（原候选 2，播放端安全限幅 `+4 dB`）、活泼可爱（原候选 4）和日常可爱（原候选 6）列入正式移植；原候选 7 改名为“备选音色（仅测试项目）”。原候选 3、5、8、9 已从测试资源中移除。

界面只保留四类预设、自由输入、重新生成并播放、回放上次结果和一键自动诊断。自由输入的 INT8 RoBERTa 会与 TTS 会话同时常驻，避免旧版每次自由输入都销毁并重新加载约 4–5 秒的 TTS 模型；相同文字继续复用特征缓存。`快看快看`只做轻量文本规范化，转换为`快看，快看`，不修改全局采样参数。

自动诊断固定使用日常认真主音色，不播放音频；依次记录一次冷启动、四类预设热推理，以及自由输入首次前处理/特征缓存对照。报告现在区分本轮冷加载与模型复用，并增加端到端等待、语义序列摘要、波形峰值/RMS/近削波比例和峰值 PSS。

## v0.3.2：多台词筛选与自由输入

本轮移除已经淘汰的候选 3，只保留完整 Chinese RoBERTa，并加入四类快捷预设：普通闲聊、疑问、安慰和活泼。每类预设都使用桌面端 Genie 前处理得到的 FP32 精确张量，便于快速、可重复地比较剩余八段参考音频。

自由输入不是零特征回退：配套模型包提供动态 INT8 Chinese RoBERTa，APK 内置 BERT WordPiece 词表，以及由 Genie 原版中文 G2P 离线整理的常用词音素词典。受单文件交付体积限制，约 352 MB 的 RoBERTa ONNX 作为独立文件导入；APK 会严格核对大小和 SHA-256。自由输入首次生成会释放 TTS 会话、运行中文前处理和 RoBERTa，再重新加载 TTS 模型，以控制峰值内存；相同文本会缓存前处理结果。当前自由输入限制为 80 个规范化中文字符，暂不支持英文。

界面支持当前候选生成、同候选连续生成三次、当前台词生成全部八个候选、原始录音回放、自由输入和分预设评分。预设与自由输入的前处理耗时会单独报告，不计入核心 TTS RTF。

## v0.3.1：Chinese RoBERTa 声调对照

代码核查发现，v0.3.0 的中文音素序列是正确的（目标字“样”为 `y + ang4`），但目标文本与九段参考文本的 `text_bert/ref_bert` 全部为零。原因是资源制作环境缺少可用的 Chinese RoBERTa 时，Genie 会回退到零张量，而旧制作脚本没有拒绝这个回退。

v0.3.1 保留全部九个候选，并提供两种可切换模式：

- **完整 Chinese RoBERTa（默认）**：目标与参考文本都使用已验证的非零特征；
- **旧版全零特征（对照）**：保留 v0.3.0 的张量，只用于同候选 A/B 听感比较。

界面会直接显示 BERT 非零元素数和“样”的音素诊断。可以生成当前候选的旧/新两版，再切换模式分别播放。RoBERTa 在制作 APK 时预计算，不把约 1.2 GB 的 RoBERTa 模型放进 APK，因此此次 A/B 的核心推理 RTF仍可直接比较。

`tools/prepare_custom_v2_assets.py` 也已加入强校验：任何中文 BERT 张量全零都会中止打包，不再静默生成缺失韵律特征的 APK。

## v0.3.0：自定义 V2 音色盲测

当前版本使用一套配对的 GPT-SoVITS V2 权重，在相同目标文本下比较九段参考音频对音色、语气和稳定性的影响。

- Android 原生 ONNX Runtime 1.22.0
- 固定使用已在目标手机上验证最稳的 CPU 8 线程
- 可播放每个候选的原始参考录音
- 可单独生成当前候选，或一次生成全部候选
- 可回放合成结果并标记“喜欢 / 一般 / 淘汰”
- 可复制推理数据和评分汇总
- 候选 3 只有 2.70 秒，低于 Genie 建议的 3–10 秒，保留作短参考对照

目标生成文本固定为：

> 你好呀，今天过得怎么样？如果有什么想说的，我会认真听你慢慢讲。

固定文本可以避免把文本差异误判为参考音频差异。候选原来的情绪文件夹名不会送入模型，也不会影响推理。

## 模型与数据说明

一个可用的 GPT-SoVITS V2 角色需要一对权重：

- GPT `.ckpt`：文本到语义；
- SoVITS `.pth`：语义到音频。

这两个文件是一套完整模型，而不是两个独立音色。训练数据集不需要整包放进 APK；运行时只需要转换后的 ONNX 权重和预先计算好的参考特征。

用户提供的原始权重、数据集和参考录音不提交到公开仓库。`tools/prepare_custom_v2_assets.py` 接收已转换的 Genie V2 模型目录、GenieData 和参考音频清单，在本地生成 Android 资源。

示例：

```bash
python tools/prepare_custom_v2_assets.py \
  --converted-model-dir /private/voice/tts_models \
  --genie-data /private/GenieData \
  --references-dir /private/references \
  --references-json /private/references.json
gradle --no-daemon :app:assembleDebug
```

生成的模型资源目录已被 `.gitignore` 排除。

## 旧版性能结论

v0.2.0 使用官方“菲比”V2ProPlus 模型测试过 CPU、XNNPACK 和 NNAPI。目标 Xiaomi 设备的持续 CPU 8 线程 RTF 约为 1.35–1.47；XNNPACK 出现提前停止的异常短音频，NNAPI 没有收益。因此 v0.3.0 的音质比较只使用 CPU 8 线程。

`RTF = 核心推理耗时 / 生成音频时长`。RTF 小于 1 表示生成速度快于播放速度；略大于 1 时仍可以通过分句和首段预缓冲实现连续播放体验。
